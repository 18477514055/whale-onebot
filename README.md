# Whale OneBot

**在手机上跑一个聊天机器人，不用服务器、不用公网 IP，数据全在你自己手机里。**

一个 Android App 管住整个机器人（登录、配置、看板、更新），一个可以单独部署的 OneBot 11 协议端负责通信。
你能只用 App 开箱即用，也能只拿协议端，把自己的机器人接进来。

当前版本 **1.2.11**（`versionCode 12012`），下载见 [Releases](https://github.com/18477514055/whale-onebot/releases)。

---

## 能做什么

- **手机就是服务器**：QQ 与机器人跑在 App 的隔离容器里，只走本机回环，不经过任何中转。
- **一键部署**：1.2.7 起有线性向导 —— 选平台 → 自动体检并修环境 → 建档 → 配模型 Key → 逐平台登录启动，全程不用自己拼路径。
- **不用梯子也能装**：下载走「官方 + 国内镜像」多源回退，任一源不通自动换下一个并记住最快的那条；镜像只负责传输，校验始终以 App 内置索引的 SHA-256 为准。
- **开箱即用的内置 QQ 机器人**：人格、记忆库、知识库、群游戏、主动发言，装完扫码就能聊。
- **什么都能改**：几十组运行端配置面板、按群设置对话模式与回复概率、模型与 Key 按用途分开配。
- **看得见**：总览、会话、调用（含注入与推理过程）、记忆、运维、亲密度、好友、插件、待对账；B站与抖音各有独立看板。
- **可拆开用**：协议端单独部署，接你自己的机器人。
- **不注入、不 Hook**：走 QQ 官方原生模块的公开接口，不往 QQ 进程里塞补丁、不改内存、不自己造协议包。
  功能面却不比常见协议端少多少。

## 这套东西由四层组成

理解这四层，才知道更新时该更新哪一块 —— **它们的版本号各自独立**。

| 层 | 是什么 | 谁在更新它 |
|---|---|---|
| **协议端** | OneBot 11 服务端。手机上是 App 内的一段本机进程，也可以单独部署；对外只有这一份契约，不按平台拆 | 随 App 或独立进程 |
| **运行环境** | 一个 arm64 Debian 根文件系统（APK 自带，首次启动铺开）。QQ 客户端跑在里面 | 很少变，独立版本号 |
| **内置核心** | 机器人本体：人格、记忆、知识库、亲密度、对话编排、控制台，以及唯一那份 OneBot 11 契约层 | 独立版本号，可比 App 更新得勤 |
| **平台插件 / 后端** | 每个平台一对：后端做协议对接（B站/抖音是我们自己的进程，QQ 是胶水 + QQ 自带 native），插件把核心接到后端上 | 各自独立版本号 |

**外壳（这个 APK）不在这四层里** —— 它只负责界面、容器生命周期和更新。

所以：**核心能单独升级，不必重发 APK**；反过来装新 APK 也不等于换了核心。
版本管理页把 App、核心、插件、环境分开列，各自带下载按钮，每个条目都校验索引里的摘要。

## 现在能接哪些平台

一个机器人是人设与运行端的主体，平台账号是它可以绑定的通道，不是几份互相独立的机器人。
内置运行端默认按机器人共享长期记忆与知识，绑定也可选择隔离。
详见[机器人、账号绑定与第三方接口](docs/logical-robot.md)。

| 平台 | 状态 | 说明 |
|---|---|---|
| **QQ** | 已可用 | App 内置容器 + 内置核心；协议端也可单独部署 |
| **B站** | Beta | 登录、配置与看板齐全；能巡看、读评论、建资料库、生成并发送评论、收发私信。**写操作默认关闭，需要显式打开** |
| **抖音** | **测试版** | 1.2.7 起合入：协议服务 + ABI 1 插件 + 视听与公开内容解读；另有实验性的内置网页登录取 Cookie。**写操作默认全部需要授权** |
| 小黑盒 | 规划中 | App 里显示为「敬请期待」 |

各平台使用独立的本机端口、账号与数据目录，互不影响。
B站细节见[私信](docs/bilibili-dm.md)与[账号动作](docs/bilibili-account-actions.md)。

## 协议端的特点

| | |
|---|---|
| 标准 | OneBot 11；HTTP + 正向/反向 WebSocket |
| 动作 | 发送、历史、群管理、群文件、请求处理、媒体下载，`get_supported_actions` 给真实清单 |
| 消息段 | text / at / reply / image / record / video / file / face / json / forward，另有两个扩展段 |
| 鉴权 | Bearer 令牌；只监听回环 |
| 失败语义 | **区分「确定没发生」和「不确定」**：`1503` 可安全重试，`1504` 不要自动重试 |
| 连续性问题 | 一次发送拿不到回执**不会**把会话锁死（多数实现会） |

接口细节、动作清单、结果码、事件格式全在 **[协议端接口文档](docs/protocol-api.md)**。

## 和常见协议端比

| | 本协议端 | 常见桥接类协议端 |
|---|---|---|
| 接入方式 | **调用 QQ 官方原生模块的公开接口**（不注入、不 Hook、不改内存、不自己造包） | 常见有 Hook 注入、内存补丁或自实现协议包 |
| 功能面 | 消息/媒体/群管理/群文件/历史/请求处理都有 | 视实现而定，花样更多 |
| 部署形态 | 手机 App 内的容器 / 也可单独起进程 | 多为 PC 或服务器进程 |
| 账号数据 | 留在手机本地 | 常常要一台常开的机器 |
| 失败语义 | 明确区分「未提交」与「结果未知」 | 很多只有一个笼统失败 |
| 发送与会话 | 发送异常不阻塞后续发言 | 容易出现「一次异常整个群哑掉」 |
| 消息段完整性 | 不支持的段整条失败，不发半条 | 有实现会静默截断 |
| 群名 | ⚠ 部分 QQ 版本拿不到，需自备映射 | 视实现而定 |
| 生态 | 新项目，插件/适配器少 | 成熟项目生态更大 |

**优点**：不注入所以稳、装完就能用、数据不出设备、失败语义清楚、不会被一次发送异常拖死。
**缺陷**：生态还小、群名可能缺失、必须用手机跑容器。

## 快速开始（用 App）

1. 安装正式签名 APK，打开后进 **QQ → 启动页**。

   **首选「一键部署」**（设置主页顶部的大卡）：它会把「选平台 → 体检并修环境 → 新建机器人 → 配模型 → 登录启动」串成一条线，缺哪步修哪步，已就绪的自动跳过，每台新机器人都能重跑一遍。

   想手动来也行：
   - 点「**启动容器**」——环境与核心都随 APK 自带，起好后这页会写「容器在运行 · 还没登录」。首次约 1～2 分钟（要铺 51 MB 环境），之后是秒级。
   - 页面上有【**运行日志**】区（容器日志 + 登录日志最后几十行），机器人起没起来一眼看到，不用连电脑。
2. 容器起来后还需要一个 **QQ 客户端**（不随 App 分发，请自行取得 arm64 的 `linuxqq` deb）：
   进「**设置 → 环境配置 → 第 3 步**」，把 deb 放进手机「下载」目录，点扫描并安装。
   全程在宿主侧解包，**不依赖容器在跑**；多个 deb 会优先选最新的。
3. 回到启动页点「**扫码登录 QQ**」，用手机 QQ 扫码。登录成功后同页显示「已登录 <QQ号>」。
   已经登录过的手机重启容器时会先试**快速登录**，成功就不需要再扫。
4. 「新建机器人」时填名字与提示词，从本机空闲列表挑核心，勾选平台。每个机器人独立安装对应插件，某个平台失败可单独重试。
5. 核心的版本、备份、恢复与释放在设置里管理。停止不释放；释放会清除该实例资料并移除其机器人，需确认。

> **测试机提醒**：`com.whaleonebot` 的正式签名包与 debug 包不能共存（签名不同），覆盖安装会清数据。
> 想在同一台机器上并存，用另一个 applicationId 的 beta 包。

## 单独部署协议端

```bash
npm ci --ignore-scripts --include=optional
export WHALE_ONEBOT_TOKEN=$(node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))")
node src/cli.mjs
```

默认监听 `127.0.0.1:13800`；请求带 `Authorization: Bearer <令牌>`。
把你的机器人当客户端接上去即可，接口见 **[协议端接口文档](docs/protocol-api.md)**。

## 已知限制

**环境与安装**

- **一台彻底干净的机器还没端到端跑通过一遍**：从首次安装到进群聊天（内置环境 → 装 QQ → 扫码 → 进群）这条完整链，只在并排测试包上验过其中若干段。
- QQ 客户端**不随 App 分发**，需要你自备一个 arm64 的 `linuxqq` deb 放进「下载」目录再在环境配置页安装。装得上不等于登得上，某个版本登不上请把版本号回报。
- 手机上的代理/VPN（如 sing-box 的 tun 模式）**可能让 QQ 的长连接变成半开**：收得到消息、发不出去，而且客户端不会自己重连。
  排查手法：`get_friend_list` 秒回但 `get_group_member_info` 十秒超时，就是这个症状。此时重启一次容器通常能恢复。
- 容器里的系统默认值（hostname 等）已按每台手机派生并补齐 `machine-id`；根分区名仍是 Android 的 `dm-*`，暂未处理。

**QQ 协议面**

- 群名补全依赖 QQ 原生回调，部分版本不触发，群列表只能显示「说过话的群」，名字退回号码。
- 群成员名单接口在部分版本上会超时（`Native query did not complete`），此时 `@` 昵称降级为「最近发言人」。
- `getMultiMsg` 拿不到聊天记录合集，合并转发类的卡片只能靠 hook，我们不做。

**模型与检索**

- 记忆与知识库的向量检索依赖外部 embedding 服务；不可用时降级为关键词检索，不会崩。
- 模型通道按需自配；网络抖动时会自动重试并有日志，但**没有离线兜底**。

**平台**

- B站分区流（按分区取推荐）在部分账号上会被服务端拒绝，此时自动回退到全站推荐，并在动作流水里写明「回退」，不会假装按分区看过了。
- B站私信回复受服务端限频约束，被限频后静默冷却再试，不会连续撞。
- B站直播、关注流、收藏夹几条来源尚未逐项实测。
- **抖音是测试版**：实验性的网页登录取 Cookie，不保证官方认证个人号的长连接稳定；写操作默认全部需要授权。
