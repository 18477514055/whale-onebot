# Whale OneBot

**在手机上跑一个聊天机器人，不用服务器、不用公网 IP，数据全在你自己手机里。**

一个 Android App 管住整个机器人（登录、配置、看板），一个可以单独部署的 OneBot 11 协议端负责通信。
你可以只用 App 开箱即用，也可以只拿协议端，把你自己的机器人接进来。

## 能做什么

- **手机就是服务器**：QQ 与机器人跑在 App 的隔离容器里，只走本机回环，不经过任何中转。
- **开箱即用的内置 QQ 机器人**：人格、记忆、知识库、群游戏、主动发言，装完扫码就能聊。
- **什么都能改**：运行端几十组配置面板、按群设置对话模式与回复概率、模型与 Key 按用途分开配。
- **看得见**：总览、会话、调用（含注入与推理过程）、记忆、运维、亲密度、好友、插件、待对账；B站另有独立看板（巡看、评论、配额、动作流水）。
- **可拆开用**：协议端单独部署，接你自己的机器人。
- **不注入、不 Hook**：走 QQ 官方原生模块的公开接口，不往 QQ 进程里塞东西 ——
  这才是它到现在**没被腾讯踢下线过**的原因。功能面却不比常见协议端少多少。

## 现在能接哪些平台

一个机器人是人设与运行端的主体，平台账号是它可以绑定的通道，不是两份机器人。内置运行端默认按机器人共享长期记忆与知识，绑定也可选择隔离。
详见[机器人、账号绑定与第三方接口](docs/logical-robot.md)。

| 平台 | 状态 | 说明 |
|---|---|---|
| **QQ** | 已可用 | App 内置容器 + 内置运行端；协议端也可单独部署 |
| **B站** | Beta | App 内有登录、配置与看板；运行端会巡看、读评论、建资料库、生成并发送评论、收发私信。**写操作默认关闭，需要你在配置里显式打开** |
| 抖音 / 小黑盒 | 规划中 | App 里显示为「敬请期待」 |

B站使用独立的本机端口、账号和机器人数据目录，与 QQ 互不影响；[私信](docs/bilibili-dm.md)与[账号动作](docs/bilibili-account-actions.md)的接口细节单独成篇。

## 协议端的特点

| | |
|---|---|
| 标准 | OneBot 11；HTTP + 正向/反向 WebSocket |
| 动作 | 发送、历史、群管理、群文件、请求处理、媒体下载，`get_supported_actions` 给真实清单 |
| 消息段 | text / at / reply / image / record / video / file / face / json / forward，另有两个扩展段 |
| 鉴权 | Bearer 令牌；只监听回环 |
| 失败语义 | **区分「确定没发生」和「不确定」**：`1503` 可安全重试，`1504` 不要自动重试 |
| 连续性问题 | 一次发送拿不到回执**不会**把会话锁死（多数实现会） |

接口细节、动作清单、结果码、事件格式全在 **[协议端接口文档](docs/protocol-api.md)**。

## 和常见协议端比

| | 本协议端 | 常见桥接类协议端 |
|---|---|---|
| 接入方式 | **调用 QQ 官方原生模块的公开接口**（不注入、不 Hook、不改内存、不自己造包） | 常见有 Hook 注入、内存补丁或自实现协议包 |
| 封号风险 | **低**：不往 QQ 里塞东西，账号行为跟正常客户端一致 | 取决于注入深度，普遍更高 |
| 功能面 | 消息/媒体/群管理/群文件/历史/请求处理都有 | 视实现而定，花样更多 |
| 部署形态 | 手机 App 内的容器 / 也可单独起进程 | 多为 PC 或服务器进程 |
| 账号数据 | 留在手机本地 | 常常要一台常开的机器 |
| 失败语义 | 明确区分「未提交」与「结果未知」 | 很多只有一个笼统失败 |
| 发送与会话 | 发送异常不阻塞后续发言 | 容易出现「一次异常整个群哑掉」 |
| 消息段完整性 | 不支持的段整条失败，不发半条 | 有实现会静默截断 |
| 群名 | ⚠ 部分 QQ 版本拿不到，需自备映射 | 视实现而定 |
| 生态 | 新项目，插件/适配器少 | 成熟项目生态更大 |

**优点**：不注入所以**稳**、装完就能用、数据不出设备、失败语义清楚、不会被一次发送异常拖死。
**缺陷**：生态还小、群名可能缺失、必须用手机跑容器。

## 快速开始（用 App）

当前是 **1.1.7**。这一版把「装环境」这一步从用户手里拿走了：**APK 自带一份公共环境与一份内置核心**（约 104 MB），
第一次点「启动容器」会自己在手机上铺开，不需要先去下载环境包，也不需要另找核心 ZIP。
第一次启动约 1～2 分钟（要写 51 MB 环境 + 释放图形库），之后**再启动是秒级**。
实际可下载版本以 [Releases](https://github.com/18477514055/whale-onebot/releases) 的资产清单为准。

1. 安装正式签名 APK，打开后进 **QQ → 启动页**：
   - 点「**启动容器**」——环境与核心都是现成的，起好之后这一页会写「容器在运行 · 还没登录」。
   - 页面上有【**运行日志**】区（容器日志 + 登录日志最后几十行），机器人起没起来一眼就能看到，不用连电脑。
2. 容器起来后还需要一个 **QQ 客户端**（它不随 App 分发，请自行取得 arm64 的 `linuxqq` deb）：
   进「**设置 → 环境配置 → 第 3 步**」，把 deb 放进手机「下载」目录，点扫描并安装。
   安装全程在宿主侧解包，**不依赖容器在跑**；多个 deb 会优先选最新的那个。
3. 回到启动页点「**扫码登录 QQ**」，用手机 QQ 扫码；登录成功后同一页会显示「已登录 <QQ号>」。
4. 「新建机器人」时填名字与提示词，从本机空闲列表挑一个核心，勾选平台。每个机器人独立安装对应插件；某个平台失败可单独重试。
5. 核心的版本、备份、恢复与释放在设置里管理。停止不释放；释放会清除该实例资料并移除其机器人，需确认。

[发行物布局、版本来源与干净手机验收](docs/github-release-delivery.md)。

## 单独部署协议端

```bash
npm ci --ignore-scripts --include=optional
export WHALE_ONEBOT_TOKEN=$(node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))")
node src/cli.mjs
```

默认监听 `127.0.0.1:13800`；请求带 `Authorization: Bearer <令牌>`。
把你的机器人当客户端接上去即可，接口见 **[协议端接口文档](docs/protocol-api.md)**。

## 已知限制

- **全新手机上的完整流程还没有走通一遍**：「内置环境 → 装 QQ → 扫码出码」这条链已在并排测试包上真机跑通（全新数据目录、无预置 rootfs），但一台彻底干净的机器（首次安装、从零到进群聊天）还没端到端跑过一遍。
- QQ 客户端**不随 App 分发**，需要你自己放一个 arm64 的 `linuxqq` deb 到手机「下载」目录再在环境配置页安装；装得上不等于登得上，某个版本登不上请把版本号回报给我们。
- 群名补全依赖 QQ 原生回调，部分版本不触发，群列表只能显示「说过话的群」，名字退回号码。
- 记忆与知识库的向量检索依赖外部 embedding 服务；不可用时降级为关键词检索，不会崩。
- **没有梯子也能装**：下载走「官方 + 镜像」多源回退，任一源不通就换下一个；但镜像只负责传输，校验始终以 App 内置的索引摘要为准。
- B站分区流（按分区取推荐）在部分账号上会被服务端拒绝，此时自动回退到全站推荐，并在动作流水里写明「回退」，不会假装按分区看过了。
- B站私信回复受服务端限频约束，被限频后会静默冷却一段时间再试，不会连续撞。
- 直播、关注流、收藏夹这几条来源尚未逐项实测。
- App 只提供 QQ 与 B站的接入；抖音、小黑盒是占位。
