## 这一版修了什么（1.1.8-beta.1）

1.1.7 发布后暴露了两个真问题，都在这版修掉。**这一版是修 1.1.7 的补丁版**，没有新功能。

### 1. 修「点启动容器什么都不发生」（★ 主要变动）

1.1.7 在一台装过内置核心的机器上**完全起不来容器**。真机日志是这样的：

```
[login] proot error: '/bin/bash' not found (root = .../files/rootfs, cwd = /, $PATH=(null))
[login] fatal error
LOGIN: exit rc=1
```

原因是**两套判据**：准备环境的那段代码判断「环境是否就绪」时会去扫 `files/core-environments/*/rootfs`，
而真正起容器的代码**只认 `files/rootfs`**。装过核心的机器上，前面那份存在、后面那份是空的，
于是上层的结论是「环境已就绪」，下面却找不到 `bash` —— 界面上就是点了没反应。

现在两边统一：**只认 `files/rootfs`**。若这个目录存在但不可用（空骨架、上次铺到一半被打断），
会先把它挪成 `rootfs.broken-<时间戳>` 留证，再重新铺 —— 因为底层铺环境时遇到已存在的目录会拒绝覆盖。

### 2. 修「点知道了，首页文字互相压印」

首页那张三步指引卡点「知道了」时会整页重建，但重建时只往容器里**又加了一列**、旧的没移除，
两层界面叠着画，文字就错位压印在一起。现在重建前会先清空，正常收起。

### 3. 换环境不再要你重装 QQ

1.1.7 之前，**每次更新环境都得重新下载/安装一次 QQ**。原因有三层：

- QQ 客户端不是 App 自带的，它装在**环境目录里面**（`<rootfs>/opt/QQ`）；
- 装 QQ 时的目标路径与容器读取的路径曾经不是同一个（退到 `core-environments` 那份去了）；
- 环境不能覆盖，只能整棵换 —— QQ 就跟着一起没了。

现在换环境时，会先把 `opt/QQ` **移到临时位置**（同分区移动是瞬时的，不复制那 1.2 GB），
新环境铺好后再**移回原位**。日志里会写「旧环境里的 QQ 客户端已暂存（铺完再放回，不用重装）」。
⇒ **只有第一次要你自己提供 QQ 安装包**；之后换版本不再需要。

- **彻底干净的手机**（首次安装 → 装 QQ → 扫码 → 进群聊天）仍未端到端跑过一遍。
- 受管核心那条「连接 QQ 拉起本机协议端」仍只做过逻辑测试与前台服务验证。
- 内置环境的 525 个库还是整套带上，没有按依赖闭包裁剪，包体依旧约 104 MB。
