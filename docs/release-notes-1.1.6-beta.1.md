## 这一版修了什么（1.1.6-beta.1）

### 1. QQ 客户端不再限定版本（★ 主要变动）

1.1.5 的白名单只认 `3.2.35`（`208717176` 字节 / `5f93ea…`）。但官方 `qqdl.gtimg.cn/qqfile/QQNTV2/` 这个前缀在**很多网络上直接 403**（第一位使用者实测：家宽、手机流量、IPv4/IPv6、8 个 CDN 节点全 403，而同主机老路径 `/qqfile/qq/PCQQ/…exe` 是 206 —— 不是封 IP，是那个前缀需要鉴权），结果新用户**没有任何版本能装上 QQ**。

现在改成：**任何 arm64 的 QQ `linuxqq` deb 都能装**，只做 Debian 结构校验（ar 头 + `control`/`data` 成员 + 521 MB 上限），不再比对版本与摘要。哪一版真能登录我们没法保证 —— 装完登录不上，请把版本号反馈给我们。

### 2. 环境配置页可以「让 App 直接下载」（新增）

按钮「让 App 直接下载（自动换源）」会依次尝试：

1. 官方元数据当前版本（`linuxConfig.js` → `armDownloadUrl.deb`）
2. 已知的 `3.2.35` 直链
3. 社区历史镜像里的 `3.2.32`（先走 `ghproxy.net` / `ghfast.top` / `gh-proxy.com` 三个镜像，最后才直连 GitHub）

每个候选先做 `Range 0-1023` 探测（只认 200/206），成功才全量下载，下完做结构校验再落地。**三个都不行时，页面会把每个源的状态原样列出来**（例如 `HTTP 403` / `DNS 解析失败`），下面的两条链接仍可手动复制。

⚠ 诚实边界：这个按钮的**真实成功率取决于你所在的网络**。本机实测：官方与 3.2.35 都是 `HTTP 403`；GitHub 与三个镜像在测试机上都是 `DNS 解析失败`（该机带分流代理）。所以它是「尽力而为」，失败会把原因说清，不假装成功。

### 3. 「容器在跑」和「QQ 未登录」不再看起来自相矛盾

原来启动页一行「容器运行中」+ 一行「未登录」，读起来像在自相矛盾。现在合成一句：

- 未登录：`容器运行中 · QQ 未登录（扫上方二维码）`
- 已登录：`容器运行中 · 已登录`
- 列表页同步：`容器在跑 · QQ 未登录（去扫码）`

### 4. 客户端版本号不再写死 3.2.35

容器脚本的 `app_version` / `QUA` / `clientVer` 以前固定是 `3.2.35-54395`；装了别的版本就会以 3.2.35 的身份登录。现在启动时读 `/opt/QQ/resources/app/package.json` 的 `version`（形如 `3.2.32-52194`），`QUA` 跟着拼；读不到才退回原值，老环境行为不变。

## 资产（14 个）

本版**只换 APK**（`whale-onebot-1.1.6-beta.1.apk` / `11601` / release 签名 `4e2e2ef3…`）；内置核心、环境包、发行索引三件与 1.1.5 相同（索引 `76723270…`，仍是 APK 内置 pin）—— 所以升级这一版**不需要重新下核心与环境包**。

## 已知未验

- 「让 App 直接下载」只做了编译验证 + 真机失败路径验证（三个源全失败时的报错是真实的）；**成功下载路径在这台测试机上无法复现**（三个域名都不通）。
- 3.2.32 能否登录成功未验（需要扫码，且没有对应账号）。
- 运行端的补课修复（`catchup` 不再重答历史）与「未发送消息交给模型」两项**没有打进这一版的核心包**（核心包与 1.1.5 相同），要等下一次核心重建。

## 升级提示

debug 包不能覆盖 release 包（签名不同）。装了 debug 的机器要先卸载。
