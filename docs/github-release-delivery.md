## 下载从哪里来

以不可变 tag `v1.1.0-rc.1` 作为测试发布候选，不把 `main` 分支的源码 ZIP 当安装包，不用可变的 latest 下载地址标识具体版本。App 使用自己的受信任目录验证下载文件，GitHub Releases 存放版本化资产：

| 资产 | 消费者 | 规则 |
|---|---|---|
| 正式签名的 Android APK | 新用户 | 不发布 debug APK；不要用新签名顶替老用户的升级链 |
| 经校验的版本目录及其可信签名/摘要 | App 安装器 | 列出模块版本、兼容 ABI、体积、散列、准确下载位置；目录自身必须有独立信任根 |
| 公共 ARM64 环境包、源与第三方许可清单 | 首次安装内置核心的 App | 从可追溯输入构建，先显示下载总量；绝不取自个人手机备份 |
| `bot-core-版本.zip` | 内置机器人实例 | 下载包可以复用；每份核心独立编号、分配和重置 |
| `bot-qq-版本.zip`、`bot-bilibili-版本.zip` | 指定实例 | 单独获取；绑定新平台只补缺包；已装插件不因另一份下载失败而丢失 |
| 独立 OneBot 协议包、部署文档 | 第三方 | 不依赖手机 App 或内置核心。QQ 原生账号接入仍需另有合法运行环境，协议源码不等于官方客户端二进制 |

预期地址形态：`https://github.com/18477514055/whale-onebot/releases/download/<tag>/<asset>`。**地址形态不代表文件已经发布。** 正式资产名、字节数和散列以最终候选目录为准。不通过 Release 附件分发账号态、API Key 或测试设备的任何数据。

## 旧包及发布门禁

2026-11-20 只读检查：公开 v1.0.1 只有 `whale-onebot-release.apk` 和 `rootfs.tar.gz`，没有独立核心/插件。旧 rootfs 的 GitHub SHA-256 为 `2df2ccb1a844b265f6e382266459b677a7ea3cf346bf6e339fe2db61cebd67f4`；不将它用作新公共环境，不覆盖同名历史资产。见 [旧资产审计](release-audit.md)。若处理既有公开资产，应单独确认处置范围。

1. 用干净源码导出构建，扫描候选源码和最终各 ZIP。检查归档内容本身，不只扫描扩展名；确认无生产资料、未经许可的二进制或真实账户默认值。
2. 验目录→归档→逐文件 SHA、模块 ABI、实际端口/路径、目标 CPU 与依赖；测试错误摘要、下载中断、磁盘不足及不兼容版本不会污染已有实例。
3. 用原正式签名身份构建 non-debuggable APK，并保存本地 release 清单。签发和上传分开：发布测试版本前由操作者确认目标 tag、提交和附件列表。不要把密码贴在聊天或写进命令行。
4. 批准后从审核通过的公开源创建测试 Release，上传附件并从公开 URL 回读核验。未经批准不创建 tag、不推代码、不上传或删除远端资产。
5. 只用明确指定的干净手机，从公开 Release 安装；检查无预置机器人/登录态，按“首次下载环境及核心→创建两份实例→选空闲核心建机器人→两平台分别登录→备份并释放一个实例→另一实例数据和运行不变”验收。生产手机不作为干净安装替代品。
