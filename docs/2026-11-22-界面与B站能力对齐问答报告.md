## 二、用户澄清的架构口径（后续一律按此判断）

> 「各个平台的接入插件仅仅只是我们的机器人需要而已；别人会自己来适配，他们只需要准备好自己的核心、接上我们预留的接口。QQ 接入插件、B 站接入插件这些全都属于内置机器人核心，只有它才需要。」

推论（写进实现取舍）：
- 平台插件 = **内置机器人专属的协议/动作层**，不承诺给第三方复用；对外只承诺「核心 + 接口」。
- 因此「巡看/评论/配额」这类**行为策略**属于运行端（核心）与产品层，插件只提供动作与协议语义（与 P5 一致）。
- 配置项放在**机器人核心的配置面**（App 里 B 站页的配置 tab → 写进实例/绑定的运行端配置），不塞进插件 CLI 开关堆里。

## 五、由此定下的实现清单（6 组）

### A. B 站页面与路由（修 3 个缺陷）
1. 平台列表只显示**本平台**的绑定；机器人卡片若同时挂 QQ 与 B 站，按平台分组显示，不再混排。
2. 「连接机器人」：平台开关关着时**不能只是 toast** —— 按钮上直接写清「先开启 B 站」并给一键开启；启动中显示进度，成功/失败都有结果行。
3. 「快速登录」：点下去立刻进入「准备中 → 启动中 → 已连接/失败原因」三段反馈；前置条件（核心受管、容器就绪）不满足时明确说缺什么。
4. 登录态可见性：卡片显示 **UID + 昵称 + 最近核验时间 + 登录来源（本机/已失效）**；并明确一句「登录只在本机有效」——因为另一台设备登录这里确实看不到。

### B. B 站行为引擎（一步到位）
巡看循环（tick）→ 选源 → 播放计时 → 读评论 → 生成评论 → 发送 → 记录 → 退避。
全部参数见第六节表格；默认值按「中等」档。

### C. B 站资料库（新组件）
- 落库维度：视频号、标题、作者 UID、作者名、分区、时长、观看秒数、评论正文、评论作者、评论时间、点赞数、是否热评、我是否在该评论下发言、对方是否回复、落库时间、来源（推荐/关注/搜索/收藏）、任务 id。
- 两张表：`bili_videos`（视频级）、`bili_comments`（评论级，含 reply 关系）；只追加，不物理删除（清理走"过期归档"）。
- 两个开关：
  - **定时清理**：`retentionDays` 之前的数据删除（默认 30 天，0=不清理）
  - **定时归纳**：`condenseAfterDays` 之前的数据调一次模型提炼成摘要（默认 7 天），**提炼成功后删除原文**，只留摘要与统计。
- 归纳结果进「知识/记忆」面，可在看板里看最近一次归纳时间与条数。

### D. 看板（B 站）
卡片：浏览与观看统计、评论与互动统计、配额与限流状态、账号档案卡、当前任务与下次执行、私信概览、**动作流水时间线**（append-only、无限追加、每页 10 条、可翻页看更早）。

### E. 设置页与版本管理
- 「环境配置」只留：容器下载 + QQ 安装包三步（入口从三份收成一份：删掉 BotListScreen 顶部与版本管理里的重复跳转）。
- 「版本管理」成为唯一版本入口，分组：
  - **App 版本**：实时读 GitHub Releases，列出全部版本（含 rc/beta），显示 tag/时间/大小/是否当前；点开给下载链接。
  - **内置核心版本**：列出可用核心版本，当前占用者、可切换。
  - **平台插件版本**：按平台列出插件版本，可单独升级。
- 「自动重启」改为右侧 Switch（整卡不响应），开的时候若系统自启动没开，弹一次引导：跳「应用详情」页（`ACTION_APPLICATION_DETAILS_SETTINGS`），一句话说明要找「自启动」。

### F. 文本瘦身（中等）
只删解释「为什么/原理」的长句与重复提示；保留：操作结果、错误原因、危险操作后果确认。

## 七、仍需你拍板的两处

1. **动作流水无限追加**与「只追加不删除」如何平衡存储：建议按月分表 + 90 天后自动折叠成统计（可关）。
2. **B 站昵称/等级/粉丝数**需要调用账号信息接口（现有 `account-actions` 里有只读能力），是否允许 B 站页每次进入都调一次（会产生网络请求与少量风控面）。
