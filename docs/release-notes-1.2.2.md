# Whale OneBot 1.2.2

修的是**扫码配对打不通**。1.2.0/1.2.1 里，扫码这条路线上有 6 个缺陷叠在一起，任意一个都能让它失败，
所以表现就是「扫了没反应」。

## 一、二维码本身之前画不出来 / 画不清

1. **码体太大**：配对 URI 里塞了 33 字节未压缩公钥 + 可派生出来的 `id=` + 默认中继列表 + 多余的 URL 转义，
   再被渲染进 `268dp` 的框里，二维码被压成 Version 16–18（约 85×85 的细密点阵）—— 手机摄像头在正常距离上根本析不出点。
   现在：**改用 SEC1 压缩 P-256 公钥（`pkc=`）**，省掉可派生字段与默认中继，去掉多余转义，
   **长度 < 220 ⇒ Version ≤ 9**，格子明显变大。
   **向下兼容**：旧版 `pk=` / `exp=` 形式的 URI 仍然能读。

## 二、相机之前拍不清楚

2. **分辨率写死 640×480**：小图 + 大二维码 = 析不出。
   现在：查 `StreamConfigurationMap` 动态挑 `~1280×960` / `1280×720` 的高清输出。
3. **预览比例与旋转错**：补全 `TextureView` 的 center-crop 比例与旋转矩阵 —— 之前画面被拉扁/转错，
   你看到的位置和真实取景框对不上。
4. **对焦不动**：显式设 `CONTROL_MODE_AUTO` + AE + AF，并支持**轻点画面重新对焦**；加了扫描光条与实时提示。

## 三、解码算法之前有硬伤

5. **二值化方法会翻车**：原来用 8×8 块均值，一遇到**暗边框**或大块黑色（二维码外侧的黑底）就整块反色。
   现在：改用**积分图 Bradley-Roth 多档自适应二值化**（先裁中心 75% 取景框、再全帧 + Otsu 兜底）。
6. **定位容易认错**：加了 45° 对角线核验 + 直角几何排序；对齐块按列垂直定心、5 点多数投票回退。

## 四、验证

- `javac --release 8` **141 个 Java 文件零错**；`BAD_UTF8: []` / `REAL_ALERTDIALOGS: []`。
- `RemoteP2pAndQrTest` **45/45 PASS**（含 1280×720、暗边框、反光、模糊、`+9°` 与 `-12°` 倾斜的模拟相机帧）。
- `ComponentIndexTest` 21/21，其余全套 Java 逻辑测试全绿。

## 五、装这一个包就行

- 版本 `12003` / `1.2.2`，release 签名，无 `debuggable`；覆盖安装，数据与登录态都保留。
- **内置部件一个字节没改**（环境 1.1.8 / 核心 1.1.8 / 两个插件 1.1.8 / 三个 1.2.0-beta.1 后端），
  索引也还是同一份，所以这次只发 APK。

## 六、未验证

- 这版**还没在真机上扫过真码**。上面所有「扫码」证据都是模拟相机帧（合成图 + 角度/模糊/反光扰动），
  不等于真机摄像头 + 真实屏幕的组合。请你扫一次真实配对码，把结果告诉我：
  1. 相机预览清不清楚、点画面能不能重新对焦；
  2. 扫到码有没有立刻反应（还是仍然没反应）；
  3. 如果失败，屏幕上给的是哪一句提示（现在会明确告诉你「不是配对码」还是「没检出轮廓」）。
