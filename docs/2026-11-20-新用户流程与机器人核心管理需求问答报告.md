# Whale OneBot｜新用户流程与机器人核心管理需求问答报告

**首次对齐：**2026-11-20，七组 28 题。**补充对齐：**2026-11-21，四组 16 题（第 29–44 题）。前 28 题保留原貌；涉及平台入口、开关、名称、QQ 获取及确认方式时，以末尾补充为准。

**阅读说明：**“答”记录用户选项或自填回答；标为“补充说明”的文字用于串联前后追问，不是额外的产品决定。本报告记录目标行为，不代表这些功能均已实现，也不构成发布授权。

**新用户主线：**安装 Release APK → 设置 → 机器人 → 下载内置核心或接入自定义核心 → 新建机器人、填写名字和提示词 → 从空闲列表选核心 → 勾选平台、安装所需插件 → 从首页进入平台，选择机器人并登录。

## 第一组｜核心是什么，何时算空闲

**01 问：首版提供多种官方核心，还是同一种核心可以创建多份？**  
答：先上一种，可创建多份；目录支持以后加种类。

**02 问：核心 01 已分给机器人“小鲸”，但小鲸已停止。核心 01 是否还出现在新建机器人的空闲列表？**  
答：不出现。未分配才算空闲，停止不释放。

**03 问：如果把小鲸从核心 01 换到核心 02，记忆和知识库跟谁走？**  
答（用户原话）：“当前版本不允许更换机器人核心。同时还有一点在机器人核心那里有一个红色警告的按钮，点击之后进行确认，就会将该核心进行释放，清空所有的内置资料，把所有的设置恢复为默认。同时提供备份到本地的选择。”

**04 问：删除机器人或解除绑定后，原核心什么时候重新算空闲？**  
答（用户原话）：“看我第三题的回答。”即以明确确认的“释放核心”为准，不因停止运行而自动变为空闲。释放对机器人、插件和账号的影响见第 05–07 题。

## 第二组｜释放、备份和第三方核心

**05 问：小鲸绑定核心 01、QQ 和 B站。确认释放核心后，原来的小鲸是否保留为草稿？**  
答：不保留。一并移除小鲸及其绑定；恢复靠备份。核心 01 清空、恢复默认设置后回到空闲池。

**06 问：释放前是否列出影响范围，并允许选择“备份到本地后释放”或“不备份直接释放”？**  
答：采用这个流程，最后再次确认。如果选择了备份，备份失败或被取消时不清空。备份排除平台登录态、令牌与 API Key；恢复后重新授权。

**07 问：释放核心时，平台账号也要退出登录吗？**  
答：删除实例插件和绑定；协议端账号单独管理，不自动退出。移除机器人的绑定与退出平台账号是两件不同的事。

**08 问：Whale 是否也给自定义核心提供自己的设置、重置或主页面板？**  
答（用户原话）：“只需要管理我们提供的内置机器人核心就可以了。他们的自定义核心不提供任何我们自己的设置，而是由他们自行接入和配置设置页面包括主界面，设置界面的所有配置全部由他们自己写，我们只提供模板和接口。”

## 第三组｜首次下载、核心看板与自定义核心登记

**09 问：新手机只安装 Release APK 后，要不要让用户自己去找容器或运行环境文件？**  
答：不要。第一次下载内置核心时，App 自动准备公共运行环境，下载前先显示总大小。

**10 问：同一版本需要三份核心时，可否只下载一次安装包，再创建三个实例？**  
答（用户追问）：“只下载一次相同的安装包，再创建三个独立核心实例的话，那么清空其中任何一个核心会不会影响到其他的？”

**补充说明：**可以共用只读安装包，不能共用可写配置、数据和插件安装状态。释放 01 时，02 和 03 不停机、不重登，数据不变，公共环境也不删除。验收时应让三个实例分别写入不同数据，在另外两个运行时释放其中一个，再核对其余实例仍能回复且数据未变。用户在第 13 题据此确认了下载方式；这项释放隔离验收不是既有分包测试的结论。

**11 问：除了编号、版本、占用者、存储用量和释放按钮，内置核心配置看板要暴露哪些设置？**  
答：核心页先只做运行信息与维护，行为策略留在机器人页。人设、提示词和平台账号不放在核心页。

**12 问：自定义核心怎样被识别为一个可选的独立实例？**  
答：同时支持导入作者的描述文件或链接，以及第三方通过本机接口主动注册。两条路径使用同一份描述格式，声明实例标识、支持的平台和作者提供的页面入口。

## 第四组｜创建机器人、安装插件与老用户升级

**13 问：隔离条件满足后，是否采用“一次下载同版本包，选择数量，创建多份独立实例”？**  
答：采用。核心列表显示每个实例自己的编号和状态。

**14 问：首页点进一个尚未接入机器人的平台，是否在此直接提供创建和下载向导？**  
答：不提供。这里只提示去“设置 → 机器人”，所有创建和下载都从那里开始。

**15 问：新建小鲸时勾选 QQ 和 B站，QQ 插件已装好、B站插件下载失败，如何处理？**  
答：保留机器人和核心占用，QQ 可用，B站标“待安装”。重试只处理缺失的包，不要求重建机器人或重装 QQ。

**16 问：已有用户升级时，原有的 `whale-1` 怎么办？**  
答：原地登记为已分配给现有机器人的内置核心实例，不算空闲。沿用当前数据，不重新下载、不复制数据、不要求重新登录，也不为登记而主动重启。

## 第五组｜协议边界、恢复、版本和交付

**17 问：第三方核心勾选 B站时，Whale 的协议端与内置机器人的平台插件是什么关系？**  
答（用户原话）：“whale-onebot应该是和napcat这种层级一样，属于协议层面的。所以所有的机器人都应该适配我们的协议。顺便一提，别人也可以完全不用我们的任何产品架构，而是在他们那里自己部署我们的协议端——然后自己打包成可用的产品。这个时候我们这个协议端就真正和napcat是一样的。”

**18 问：本地备份恢复到哪里？**  
答（用户原话）：“可以在设置页面加一个备份按钮。备份到任何空闲的核心上面，或者是彻底删除。”第 23 题进一步区分了备份、恢复和删除备份。

**19 问：已创建的机器人移除某个平台时，默认删除哪些内容？**  
答：移除前列出受影响账号并确认。停止、移除本实例的相关绑定；同平台还有其他账号时保留插件，否则卸载该实例的对应插件。保留机器人、人设和共享库，不自动退出协议端账号。

**20 问：多个已配置实例如何升级核心或插件？**  
答（用户原话）：“可以在设置界面集中管理，可以下载任何一个版本的核心或者平台兼容插件。也可以随时将现存的升级或者是回退到任何一个版本，同时也提供自动更新的能力。”兼容性和自动更新的默认值见第 21、22 题。

## 第六组｜更新细则与验收确认

**21 问：官方核心和插件的自动更新默认怎样工作？**  
答：统一在设置页开关，默认只提醒。这里的更新源是我们仓库发布的核心和插件，不是自动跟随第三方上游。

**22 问：遇到不兼容的核心、插件或旧数据格式时，版本列表和回退怎么处理？**  
答：默认只列兼容版本，另有“查看全部版本”；不能安全回退时提示需要备份。

**23 问：“设置 → 备份”是否明确区分备份、恢复和删除备份？**  
答：对。可将机器人备份到本地，选择一份备份恢复到任一兼容的空闲内置核心，或单独永久删除备份。删除备份不删除正在使用的机器人。

**24 问：创建机器人时，是否必须先登录所选平台账号？**  
答：不要求。先完成建档和插件安装；之后通过首页各平台的启动页分别登录。首页按实际情况显示已配置或待登录。

## 第七组｜页面布局、设置归属和交付线

**25 问：“设置 → 机器人”的同一页怎样排列？**  
答：顶部放“下载内置核心”；下面放“本机核心”，展示空闲数量、实例编号、来源、版本、占用者；再放“新建机器人”和已有机器人列表。同页分区。备份和版本管理在设置中另设入口。

**26 问：模型服务、Key、回复策略、记忆和知识库设置放哪儿？**  
答：在机器人详情分组管理，与名字、人设、提示词属于同一台机器人。平台页只放账号及平台特有设置。

**27 问：打开自动更新后，发现新版本时机器人正在聊天，是否立即重启？**  
答：后台下载，下次正常启动时切换，不为更新中断聊天。

**28 问：下一阶段做到什么算验收？**  
答：本地实现后，用干净设备验真实仓库下载；发布测试版本前再单独确认。需求报告本身不是开工、发布或改动现有手机的指令。

### 第九组｜一键安装、主题现象、平台导航、名称含义

| 题号 | 问 | 已确认的答复 |
|---|---|---|
| 33 | 下载包体必须来自我们仓库，还是用户体验优先？ | **App 内一键安装即可**，用户不用电脑，也不跳到官网选架构。由维护者在仓库维护验过的兼容版本、官方地址和摘要；不要求重托管专有包，不把仅获取到版本号算作安装成功。 |

| 35 | 最希望沿用 QQ 页的什么？ | 内置机器人统一为「平台 → 机器人 → 启动／配置／看板」，点入口进入独立页，不在 B 站一页堆三组操作。统一导航，不要求各平台拥有相同指标；第三方核心仍自行提供页面（第 08 题）。 |
| 36 | 机器人改名意味着什么？ | 只改 App 中所有展示该机器人的地方，包括平台列表、核心占用者和通知；不改内部 ID、平台昵称或人设自称。不再用机器人的代码或默认名作日常标题。 |

### 第十组｜常态文案、确认方式、下载进度、关闭以后

| 题号 | 问 | 已确认的答复 |
|---|---|---|
| 37 | 常态页面要留多少文字？ | 用户选「正常只留按钮」。除辨认对象所需的名字外，用动作明确的按钮引导操作，不堆说明文字；状态细节进详情。出错和危险操作只在发生时给出必要信息，保留读屏标签。 |
| 38 | 怎样统一弹窗？ | 应用内连确认也尽量不用弹窗：表单、长选择和危险操作进独立页面。确认改位置，不取消备份失败不释放等原有保护；系统权限、USB 安装和文件选择仍由系统处理。 |
| 39 | 下载本地容器时离开页面怎么办？ | 后台继续，回来仍看得到同一任务的进度。下载时展示真实已下字节／总量；校验、解包分阶段显示，不用假百分比。用户未要求必须有通知栏进度。 |
| 40 | 关闭平台出口后重开 App 呢？ | 记住关闭，不退出平台账号，不积压待补发消息。手动开启才恢复；若平台已明确判定登录失效，须本人重新授权（D285）。 |

### 第十一组｜加平台、重名与迁移、复现入口、首次开启

| 题号 | 问 | 已确认的答复 |
|---|---|---|
| 41 | 已有机器人加平台而缺插件，如何保存？ | 「设置 → 机器人 → 小鲸」用一个「保存并安装」按钮，显示本次实际下载量；命中缓存不重复下载，失败只重试新平台的缺包，原平台不停。 |
| 42 | 新建、重名和旧机器人怎样处理？ | 创建时名称必填，不允许重名；旧机器人原地改名，保留内部 ID、授权和数据。无名的给命名入口，不强迫重建。 |
| 43 | 从哪个页面复现主题问题？ | 用户指定：**主题页本身**就有看不清的字。先在这里验证主力机六套、备用机深浅色的差异，再覆盖按钮、表单、详情等共用控件。无需提供登录码截图。 |
| 44 | 新加平台还未登录时，开关是什么状态？ | 默认关闭；点开启后进入登录，取消不算开启。成功登录、协议身份核验、机器人已连接分别判断，不能仅凭开关开启就显示在线。 |

**实施与验收边界：**修改 UI 前先加载 UI 技能并读现有实现；以现有 Android 原生界面为基础。本次只对齐需求，不覆盖设备、不发布。主题缺陷根因、B 站官方同机直达能力、QQ 包体在手机端的可达性及兼容性、离页下载进度，仍需分别实测。
