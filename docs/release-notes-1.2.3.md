# Whale OneBot 1.2.3

这一版修两件**真机上一定撞到**的事：跨网络扫码配对连不上，以及更新下载完不弹安装器。

## 一、跨不同 Wi-Fi / 5G 时，扫码配对了但连不上

扫码本身在 1.2.2 已经能用，但**两端不在同一个网络**时握手仍然失败。查下来是四个原因叠在一起：

1. **UDP 打洞端口对不上**：`RemoteHostServer` 打洞时新开了随机端口，和之前广播出去的 `host` 信标端口不一致；而且只等 3.2 秒就放弃。现在严格按本次 `sid` 匹配 `host_punch`，等待放宽到 5.5 秒。
2. **组网地址被跳过**：`localIpv4()` 把所有 `100.64.0.0/10` 当成不可用，而那正是 Tailscale / 各类 VPN 组网常用的地址段 —— 于是明明有一条直连路径却被丢弃。现在 `buildIpv4Endpoints` 会把这段也作为候选。
3. **对称 NAT / 代理下没有兜底**：双方都在 CGNAT 后面（或一方挂着 `sing-box tun0`）时，打洞无论等多久都不会成功。新增 **`NostrRelayChannel`** —— 基于已有的 `NostrSignaling` 建持久多中继长连接，AES-256-GCM 分片加密 + ACK 重传，**依然零自建服务器**。它在 L4 自动降级启用。
4. **失败时只报第一句**：以前只报局域网超时那一句，看日志根本判断不出卡在哪一层。现在把**全部通道的诊断合并**汇报。

## 二、更新下载完了，安装器不弹

- **根因（铁证）**：`VersionScreen.startAppUpdate()` **从头到尾没有调用过 `watchUpdateDownload()`** —— 广播接收器压根没注册，所以下载完什么都不会发生。而且下载状态挂在**非缓存的页面实例字段**上，一离开这个页面状态就丢。
- **现在的做法**：改成**跨页面静态跟踪** + 用 `ApplicationContext` 注册广播 + **每秒用 `DownloadManager.Query` 轮询**进度与完成状态（MIUI 会丢广播，只靠广播不可靠）。用 `AtomicBoolean` 保证幂等、不会重复拉起安装器；前台直接拉起系统安装器并实时显示 `MB / 百分比`。

## 三、验证

- `javac --release 8` **142 个 Java 文件零错**；`BAD_UTF8: []` / `REAL_ALERTDIALOGS: []`。
- `RemoteP2pAndQrTest` **50/50 PASS**（新增：在本地 WebSocket 模拟中继上跑完整的 `NostrRelayChannel` ECDH/ECDSA 握手 + 加密 RPC 闭环）。
- `ComponentIndexTest` 21/21，其余全套 Java 逻辑测试全绿。

## 四、安装

- 版本 `12004` / `1.2.3`，release 签名，无 `debuggable`；覆盖安装，数据与登录态保留。
- 内置部件与 1.2.2 一个字节没改（环境/核心/插件仍是原版本），索引仍是同一份，所以这次只发 APK。

## 五、未验证

- **跨网配对仍没有真正跨两台设备、跨两个网络的实测** —— 上面第 1、3 条的证据是本地模拟中继上的加密握手闭环，不等于真实对称 NAT 穿透成功。
- **「下载完自动弹安装器」也没在真机上验证过**；而且这段代码在 1.2.2 里是坏的，所以你手上那版点了更新下载完不会有反应。
- 请你回填：① 两台设备在不同网络下扫同一张码，屏幕上给的是哪一句诊断；② 更新下载到 100% 后是否自动弹出安装器（如果没弹，隔几秒会不会补上）。
