## 这一版修了什么（1.1.7）

这一版的主题是**「装」**：以前要在手机上跑起机器人，得先下环境包、再下核心、再想办法把 QQ 客户端塞进容器，任何一步错都只能看着一句「失败」。1.1.7 把前两步收进了 APK，只留下「QQ 客户端要你自己给」这一件必须由用户做的事。

### 1. App 自带一份公共环境与内置核心（★ 主要变动）

安装包从约 1.5 MB 变成约 **104 MB**，因为里面直接放了：

- 一份公共环境（51 MB，解压后的 rootfs 骨架）；
- 一份内置核心（2.3 MB）；
- 让 QQ 客户端能跑起来所需的 **native 桥（4 个二进制）+ 一套图形/网络库（525 个 `.so`）**。

第一次点「启动容器」时，App 自己在手机上把环境铺开，**不需要先去下载环境包，也不需要另找核心 ZIP**。
第一次约 1～2 分钟（要写 51 MB + 释放库），**之后每次启动是秒级**。

### 2. 启动从「几分钟」回到「几秒」

上一版每次启动容器都会把 500 多个库文件重写一遍、并对每个文件 fork 一次 `chmod`。在真机上表现为「点开之后干等好几分钟，看起来像卡死」。
现在：

- 该释放的目录里写一个 `.whale-gui-ready-v1` 印记，**已就位就不再重写**；
- 老环境（完整 Debian 骨架那套）**根本不会走到这段代码**——它本来就不缺这些库。

真机实测：点开 App 到 `BOT: started` **2 秒**。

### 3. 启动页重做

- **新号与老号是同一页**：不用再在两个长得不一样的页面之间猜自己在哪。
- **页面里带【运行日志】**：容器日志与登录日志的最后几十行直接显示，机器人有没有起来一眼能看到，不用连电脑。
- **只显示 QQ 的状态**：以前 QQ 的启动页会串出别的平台，现在不会了。
- 同一页提供「启动容器 / 停止容器」「扫码登录 QQ / 换一张码」「保存二维码到相册」。

### 4. 装 QQ 这条路彻底修好

上一版在内置环境上装 QQ **一定失败**，报的是 `/bin/bash: line 1: rm: command not found`——因为内置环境不是完整 Debian，只有 `bash`/`node`/`env`/`sleep` 这几个命令，连 `rm`、`tar`、`xz` 都没有。现在：

- 解包**全部放在宿主侧**用 busybox 做（`xz -dc` → `tar -xf` → `cp -a`），既不依赖容器在跑，也不依赖环境里有什么命令；
- `data.tar.gz`（gzip 而不是 xz）不再被误当成 xz 去解；
- 全程 `try-finally`，不会再留下 1.2 GB 的临时目录；
- 下载目录里有多个 deb 时**按修改时间倒序挑最新**的那个；
- 失败时把 busybox 的真实输出带出来，不再只给一句「安装失败」。

### 5. 扫码登录真的能出码

内置环境这条路以前点「扫码」什么都不发生，或者干等 40 秒没有码。三个原因都修了：

1. 登录动作曾被「是不是受管环境」一刀切拦掉（现在只拦「起机器人」这一件事）；
2. 环境包里没有 `/opt/whale/native/`，登录脚本第一句 `dlopen` 就 FATAL（这 4 个文件现在随 APK 发）；
3. 缺一整套 X11/GLib 系图形库（525 个 `.so` 随 APK 发）。

真机实证：`loader ok → engine init ok → login-connected → requesting-qr → qr-ready bytes=599`，屏幕出现二维码与倒计时。

另外，容器日志现在**同时写进 logcat（tag `WhaleLog`）**——正式包没有 `run-as`，以前那部分日志等于不存在。

### 6. 发送层：不再「能收不能发，还查不出为什么」

真机上出现过一次「进程活着、消息在进、外发全被拒，持续六小时没人知道」。这一版针对它做了四件事：

- **身份探针失败时保留真实原因**：以前统一写成一句 `identity probe failed`，现场无从下手；现在会写成 `http identity probe failed: Error ECONNREFUSED syscall=connect addr=127.0.0.1:13800`，两条通道都挂时把被放弃的那条原因也并进最终消息。
- **瞬时失败重探一次**：只在 1 秒内返回的连接类失败上重探（`ECONNREFUSED`/`ECONNRESET`/`EPIPE` 等），超时**不重探**（已经花掉 10 秒预算，再探会撞穿调用方 15 秒死线）；身份不符**永不重试**。
- **HTTP 通道挂了不再让 WS 陪葬**：HTTP 端点卡住时，改用**已经验过身份**的 WS 通道发出；严格绑定模式下仍保持双通道要求，不降级。
- **连续 3 次发不出去会喊一声**，恢复时再喊一声——启动页的运行日志看得到，不必再靠「它好像不回我」来判断。

### 7. 界面与体验

- 高频的系统黑框 `AlertDialog` 换成了 App 自己的底部面板（主题色、可滚动、窄屏不溢出）；
- 「版本管理」里补回了「下载与创建新核心」入口（上一版把这个入口删没了，只能看着）；
- 本机 QQ 账号的绑定不再要求填外部 OneBot 的 HTTP/WS 地址；
- 平台插件安装失败时不再静默，会把原因说出来。

## 已知未验

- **真人扫码登录整链**：出码这一段已在真机验证，登录到进群聊天需要账号，尚未完整走一遍。
- **彻底干净的手机**（首次安装、从零到进群）还没有端到端跑过一遍。
- 受管环境的「连接 QQ」拉起本机协议端这条路径，只做了逻辑测试与前台服务验证，尚未与运行端完整联调。
- 内置环境的 525 个库目前是**整套**带上的，还没有按 `wrapper.node` 的真实依赖闭包裁剪，所以包体偏大。

## 升级提示

- 从 1.1.6 及更早版本升级：直接覆盖安装即可，机器人数据、记忆与知识库都保留。
- **debug 包与 release 包签名不同，不能互相覆盖**；装过 debug 的机器要先卸载再装正式包（会丢该机的机器人数据）。
- 装完如果 App 里显示「容器已停止」，点一次「启动容器」即可；不需要重新装环境或核心。
