# QQ 客户端取包路径：为什么新用户卡住，以及现在怎么走（2026-11-23）

第一个使用者反馈（截图原话）：「这条路径现在只有三个选择：找一份别人已经下好的 3.2.35 arm64 deb／给作者提 issue／先绕开 QQ 用 B 站」。
下面是核实结果 —— **有一部分是我们的 bug，不是腾讯把包下架了。**

## 一、我们的 bug（已修）

环境配置页「第 1 步」让用户复制的链接原本是：

```
https://qq-web.cdn-go.cn/im.qq.com_new/latest/rainbow/pcConfig.json
```

那是一个 **JSON 配置文件**。用户在电脑上打开只会看到一坨 JSON，一个下载按钮都没有 —— 拿不到 deb 是必然的。
**已改**（`ui/EnvConfigScreen.java`）：

- 一级入口 → 官方下载页 `https://im.qq.com/linuxqq/index.shtml`（电脑浏览器打开、点「ARM 版下载」），按钮「复制下载页链接」；
- 兜底 → deb 直链 `https://qqdl.gtimg.cn/qqfile/QQNTV2/9.9.37/release/816b3c79/QQ_3.2.35_261103_arm64_01.deb`，按钮「复制 deb 直链」；
- 拒绝理由从「不符白名单（大小不对）」改成写清「要 3.2.35 的 arm64 原版包（199 MB，文件名形如 QQ_3.2.35_…_arm64_01.deb）。你放的：…」。

## 二、腾讯那边的真实情况（我们只能如实说）

`qqdl.gtimg.cn` 上**所有文件**在**我们这条出口**都是 403 `Lego Server`（2026-11-23 10:1x 实测）：

| 目标 | 结果 |
|---|---|
| `…/QQ_3.2.35_261103_arm64_01.deb`（Range 0-2047） | **403**，0 字节 |
| `…/QQ_3.2.35_261103_amd64_01.deb` | 403 |
| `…/QQ_3.2.35_261103_arm64_01.AppImage` | 403 |
| `…/QQ_9.9.37_261103_x64_01.exe`（Windows 安装包） | 403 |
| `qqdl.gtimg.cn/` 根路径 | 403（COS XML 报错，449 字节） |
| `cdn-go.cn/…/linuxConfig.js`（元数据） | **206 / 200**，正常 |
| `dldir1.qq.com/…`（另一台 CDN） | 404（路径不通用） |

换 UA（curl / 无 UA / Chrome / 安卓 Chrome）、去 Referer、加 Range、以及用 Chromium 自带的网络栈请求 —— **全部 403**；
同一台手机上容器里 `curl` 也是 403 / 0 字节。
⇒ 要么这条出口 IP 被腾讯网关拒了，要么直链需要下载页签发的临时授权参数（本仓库 `docs/qq-client-candidate-3.2.35.md` 记录的取得方式就是「经腾讯下载授权流程」）。

**不能据此说「全世界都下不了」**：NUR / AUR / Flathub 的打包清单用的就是同一个 `qqdl.gtimg.cn` 直链，它们的 CI 能构建成功。
所以更可能是**我们的出口**（代理 / 机房 IP）被拒，而不是文件下线。

## 三、现在能立刻让新用户跑起来的两条路

1. **本人转交**（最快）：`/sdcard/Download/QQ_3.2.35_261103_arm64_01.deb`，208,717,176 字节，SHA-256 `5f93ea62…34cf2`，
   已在真机上被 App 扫到并通过校验（截图 `.tmp/env-qq-scan3.png`）。直接把这个文件发给对方（网盘 / 微信传文件），比让他在电脑上折腾快得多。
2. **官方下载页**：电脑浏览器打开 `https://im.qq.com/linuxqq/index.shtml` → 「ARM 版下载」→ 把 deb 放进手机 `Download` 目录 → App 里「扫描下载目录」。

## 四、还开着的两件事（需要用户拍板）

- **要不要把这份 deb 作为 Release 资产托管？** 好处是所有新用户一键可用；代价是我们**分发腾讯客户端二进制**（此前口径是「不分发」，`EnvConfigScreen` 里的注释也这么写）。
- **要不要让 App 自己下？** 技术上可做（读官方元数据 → 拿直链 → 分块下载 + 长度/SHA-256 校验），但**在我们这条出口上一定会 403**，
  所以只能做到「失败时说清是腾讯拒绝（403），大概率是开了代理/VPN，请关掉或用电脑下」——真实网络下能不能下成功，我这里验不了。
