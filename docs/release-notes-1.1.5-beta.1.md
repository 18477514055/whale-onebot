## 这一版修了什么（1.1.5-beta.1）

> 承接 1.1.4-beta.1，全部是「已有功能本来不工作」的修复，没有新增平台。

### 0. 群历史读取：每次启动的补齐都失败（真机 886 次 1502）

这是真机日志里**最高频**的失败：`get_group_msg_history` / `get_friend_msg_history` 一直回
`1502 Native query did not complete`，于是机器人启动时「补齐历史上下文」这一步从来没有成功过
（真机上 886 次），群里的上下文只能靠当场那几条。

真因不是超时、也不是内核不支持：

- 内核 `getAioFirstViewLatestMsgs(peer, 10)` 实测 **29ms** 就返回 `result:0` + 10 条消息；
- 但我们随后用 **(msgId, msgSeq) 双重去重**，而群里的**灰条**（`elementType 8`、`senderUin "0"`，
  比如入群提示、群公告变更）与真实消息**共用同一个 msgSeq**（实测两条都是 `831719`）
  ⇒ 合法响应被判成「响应畸形」→ 1502，而协议核心又把措辞统一成
  「Native query did not complete」，于是一直看不出真正原因。

改法：唯一性只认 `msgId`，`msgSeq` 只当翻页游标；灰条这类系统条目跳过并计数
（`historySystemSkipped`），不再让它毁掉整页。**真机复验：1502 → 0**（取 10 条返回 9 条、
取 50 返回 47 条、取 100 返回 94 条 —— 差的就是那些灰条）。

### 0.5 停止容器再启动后，机器人不会自己回来

「停止容器 → 启动容器」之后容器明明就绪了，QQ 协议端（13800）却一直没人监听，
`container.log` 里也不会出现那句 `容器就绪 → 自动启动机器人` —— 表现就是机器人静默掉线。

真因：`ContainerService.autoBotStarted` 是 `static volatile`，跨「容器停止/启动」保留为 `true`，
于是同一个 App 进程里第二次起容器时自动拉起机器人的条件恒假。

改法：每次 `boot()` 真正启动容器进程之前把它复位（这个标记本来只想保证「每次就绪只拉起一次」）。
**真机复验**：同一个 App 进程内连续两次启动容器（05:10:18 / 05:11:00），两次都打出自动启动；
`bot.json` → `phase: agent-running`，OneBot 13800 回 `retcode 0`。

### 0.7 环境配置页的 QQ 取包入口给了个 JSON（新用户第一道坎）

第一个使用者反馈：按环境配置页的指引去电脑上下载 QQ 客户端，**下不到**，以为只能「找别人要一份改好的包」。

原因在我们这边：那一页让用户复制的链接是 `pcConfig.json` —— 一个 **JSON 配置文件**，在电脑浏览器里打开只会看到一坨 JSON，没有任何下载按钮。

现在改成两层：

- 一级入口 → 官方下载页 `https://im.qq.com/linuxqq/index.shtml`（电脑浏览器打开、点「ARM 版下载」），配「复制下载页链接」按钮；
- 兜底 → deb 直链（`qqdl.gtimg.cn/…/QQ_3.2.35_261103_arm64_01.deb`），配「复制 deb 直链」按钮；
- 放错包时说清差在哪：从「不符白名单（大小不对）」改成「要 3.2.35 的 arm64 原版包（199 MB，文件名形如 `QQ_3.2.35_…_arm64_01.deb`）。你放的：…」。

**仍然只接受 3.2.35 arm64 原版包**（大小 + SHA-256 都对才放行），别的版本会被拒绝 —— 这是为了避免装到改过的包。

⚠ 若你在电脑上点官方下载页仍然报错/打不开：那是腾讯下载网关（`qqdl.gtimg.cn`）拒绝了**你的出口 IP**（我们实测：该主机上连 Windows 安装包都回 403），换手机热点或关掉代理再试；也可以直接找一位已经装好的朋友把那份 deb 发你。

### 1. B 站私信：从「一条都不回」到真能回

上一版私信「收得到、回不出」，根因有三个，全在运行端宿主侧：

- **宿主把生成器丢了** —— `startBiliBehavior()` 只把 `summarize` 转交引擎，`generateComment` /
  `generateDmReply` 根本没接。于是生产环境里「生成评论」「回私信」从来没生效过，日志只会写
  `dm_reply_skipped: no-generator`。现已补上。
- **一次读失败冻结全局 15 分钟** —— `bili_dm_inbox` 偶发 1500 会把整层设成退避，半夜的私信
  一条都没轮询。改为读失败只对该动作做 60 秒 → 5 分钟递增冷却，**永不设全局退避**（写失败才退避）。
- **「记过但没回过」永不重试** —— 首次回复失败后，去重键已落库，此后这条消息永远跳过。改为按
  `repliedKey` 判断，没回过就照常走回复；每个「不回」的分支都记 `dm_reply_skipped` 原因，不再静默。

另外两点：私信不再受作息窗限制（作息只约束主动巡看）；`admin.uid` 现在真的会被写进
`shared_prefs/bili_settings.xml`（此前那个文件不存在，读到的永远是空默认值）。

**真机结果**：主号发「现在能回我吗？」→ 出现 `dm_replied` → 独立回读会话，最新一条是
`mine:true`「在的，刚看到消息，你说吧」，未读归 0。

### 2. QQ 看不了视频 / 图片

不是视觉模型不支持（设备上 `api.vision` 本来就是 true），是**库里存的媒体地址带 rkey、会过期**：
直连一律 `HTTP 404`（真机日志 17 次 404 + 11 次「图片地址不合法」）。现在分两条路兜底：

- **图片**：直连失败会回退到协议端 `get_message_images`，按 `message_id` 从原生消息元素重新取。
  真机旁证：对历史里的真实图片调用它，返回的是 **base64 内联字节**（52 769 字符）——原生传输
  真的把图取回来了，不是再给一个会过期的地址。
- **视频**：新增协议动作 `get_message_videos`，把视频原生落到本机磁盘并返回**绝对路径**；
  运行端新增 `framesFromLocalVideo(path)` 直接读文件抽帧（两端在同一个容器文件系统里，
  不过网络、不会过期）。视频仍是抽 4 帧拼 2×2 四宫格。


### 3. 本机转写（ASR）路径

配置里的 `asr.localBin / localModel` 还指着 Termux 老路径（`/data/data/com.termux/...`），
容器里根本不存在，而这个值又被无条件采信 ⇒ 语音转文字永远失败且只有一句含糊报错。现在：

- 配置指向的文件**不存在**时不再采信，自动探测 `<数据目录>/asr` → `ROOT/models` → `~/.cache/whisper.cpp`；
- 存在但**跑不起来**仍旧如实报错，并且「路径不存在」与「跑不起来」分成两句不同的错误；
- `spawn` 时把二进制所在目录加进 `LD_LIBRARY_PATH`（`libwhisper`/`libggml` 就在同目录）。

⚠ **已知限制**：设备上那份 `whisper-cli` 是 **Android/Termux 版**（缺 ELF 解释器），在 Debian
容器里 `chmod +x` 后仍报 `cannot execute: required file not found`。所以本机转写在这台手机上
**仍然不可用**，只是现在会明确告诉你原因，而不是含糊失败。要真能用需换 Debian arm64 版二进制，
或改走在线转写。
